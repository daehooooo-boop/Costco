# 이번 주 코스트코 기획서

## 한 줄 정의
코스트코 가기 전에 "오늘 내 지점 여나, 이번 주 뭐가 싸나, 다들 뭘 사나"를 한 화면에서 확인하는 서비스.

## 결정

| # | 결정 | 이유 |
| --- | --- | --- |
| D1 | 완전 자동 운영, 관리 화면은 나중에 | 매주 손으로 입력하는 서비스는 오래 못 간다 |
| D2 | 할인·인기는 코코달인, 보조로 코스트픽 | 코스트코 공식 사이트는 자동 조회를 막아 둠. 코코달인은 기간·할인액이 있고 전국 공통, 코스트픽은 개봉역점 매대 가격 |
| D3 | 매일 07:00 KST GitHub Actions가 수집 → data/ 커밋 → Vercel 재배포 | 서버·DB 없이 무료. 하루 약 50회 요청 |
| D4 | 휴무 = 직접 입력 > 지점 공지(코스트픽) > 규칙 | 규칙만으로는 울산점 12/9처럼 바뀐 날을 못 잡는다 |
| D5 | 인기 TOP 10은 코코달인 인기 순위 | 네이버 데이터랩은 API 키가 필요하고 정한 키워드끼리 비교만 해 줘서 상품 순위로 못 쓴다 |

## 구조
- `data/stores.json`: 20개 지점(영업시간, 주소, 휴무 규칙). 일산점 수요일, 대구·대구혁신도시점 월요일
- `data/holidays.json`: 설·추석 당일(전 지점 휴무). 매년 1월 다음 해 추가
- `data/deals.json`, `popular.json`, `closures-announced.json`, `meta.json`: 수집기가 씀
- `data/manual/overrides.json`: 직접 입력. 휴무 추가·취소, 할인 추가·숨김·수정, 쿠폰북, 공지

## 리스크
- 출처 사이트 구조 변경 → 결과가 20개 미만이면 그 출처는 직전 데이터 유지, 화면에 안내
- 출처 사이트가 막음 → 다른 수집 사이트로 바꾸거나 관리 화면으로 넘어감
- 앱 쿠폰북은 공식 앱에만 있어 자동 수집 불가 → 관리 화면 단계에서

## 열린 질문
- 관리 화면 방식: overrides.json을 GitHub API로 고치는 작은 페이지(1~2분 뒤 반영) vs Neon DB(즉시 반영)
- 지점 선택을 위치 기반으로 자동 추천할지
